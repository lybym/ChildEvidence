## 2. 产品目标与已确认需求

目标是把持续学习、相互协调的儿童教育专业团队所提供的支持，转化为可以普惠交付的能力。产品提供融合教师、教练、心理支持等专业视角的连贯角色，帮助儿童完成基础教育中的学习任务、改善困难、探索兴趣与发展优势。

这不是仅面向研究人员的文献管理工具，也不以角色提示词或知识问答作为最终验收成果。科研基础设施继续独立存在；成长支持插件是同一项目面向 Harness 的专业能力交付层。

| 编号 | 已确认需求 | 设计约束 |
|---|---|---|
| R1 | 同时利用经典与最新研究，覆盖论文、报告、调查研究等 | 记录来源类型、时间、局限、分歧和更新；新近或高引用不能替代质量评价 |
| R2 | 以插件向通用 Harness 提供专业能力，首个宿主 DSH | 原生插件含工具与运行逻辑；不能只复制一组 Skill 或人格提示词 |
| R3 | 教育判断、支持行动、复盘、人格和表达方式都来自本地科研生产成果 | 统一产出可追溯的专业资产；运行时不得静默改写已发布方法 |
| R4 | Harness 统一处理语音、文字、拍照与 Web 输入后交给插件 | 插件不建设 ASR、OCR 或前端；输入保留来源和不确定性 |
| R5 | 服务对象可为儿童、家长或教师 | 分离请求者、学习主体、回应对象和实际权限；角色名称不授予数据访问权 |
| R6 | 当前重点为学习困难、兴趣培养、潜力探索 | 从互动中积累观察，不要求家长预先完成兴趣或能力分析 |
| R7 | 本地科研生产，云端知识服务，私下交付 | 云端提供通用专业资产，个人上下文留在宿主环境；不依赖 LumiThink |
| R8 | 首阶段低风险日常学习、教育及一般情绪支持 | 不包含个体诊断、治疗、高风险干预或智力/天赋定性 |
| R9 | 希望由 AI 承担研发与科研生产，无第二名人工 Reviewer 的现实条件 | 工程自动化与科研可信性分别处理；审核发布路线尚未决策，不能冒充 Gold |

首个试用对象的私人信息不写入本仓库。可复用产品范围先覆盖小学中段；具体年龄、年级、身份及长期记录由宿主管理。本设计中的案例均为合成，不是任何真实儿童的画像或使用结果。

## 3. 最小可用成果

安装 DSH 插件后，Harness 能通过统一接口完成一个跨至少两次互动的支持过程：了解当前困难、选择有依据的方法、实施支持、提供可选探索、保存有限观察，并在后续互动中调整。

MVP 必须同时呈现：

- **改善困难**：在真实任务层面了解卡点，比较候选解释，不凭一次错误形成固定标签。
- **探索兴趣与优势**：适时提供选择和适当挑战，允许拒绝；区分新鲜感、持续兴趣、当前表现与学习后的变化。
- **连贯的专业角色**：人格稳定，方法可适配；同一角色协调学习、动机、情绪和发展视角，无需模拟一群互相发言的专家。
- **可追溯且可修正**：研究发现、应用推导、观察和假设分开；方法版本与支持结果能够对应。
- **普惠成本**：复用专业资产，按需加载；记录每次支持成本和延迟，不默认每回合多模型辩论。

MVP 不交付完整义务教育课程库、全量儿童测评系统、专业诊疗、独立语音/图像模型、自己的聊天应用或云端儿童档案平台。教学内容和题目正确性仍须明确来源与校验，不能因为有教育心理方法就宣称覆盖全部学科教学。

## 5. 本轮不越过的边界

遵循 [AGENTS.md](../../../AGENTS.md)：不读研究摘要、PDF 正文或 Docling 衍生全文给模型；不读真实儿童数据；不生成研究结论；不代签 CE-01R；不打开模型访问门禁；不将 AI 草稿升级为正式教育行为。

允许并需要讨论治理改造，但讨论不等于政策已经生效。尤其是“AI 全流程生产如何获得发布资格”以及“人格原则如何版本化演进”，必须在实施前形成明确决策；详见 [待决策事项](delivery-plan.md#5-待决策事项)。
