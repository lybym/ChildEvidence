# CE-POL-01：公开科研资料用于 Codex AI 审查的轻量政策（提案）

> **状态：DRAFT / 未生效** · 2026-10-14。此文件用于替代 PR #8 原先复杂的多角色、逐段审批方案。**PR 合并不等于政策生效，不能凭本提案绕过当前 `ANNOTATION_GUIDE.md` §9 的禁止出站规则。** 生效需要项目负责人明确确认，并由后续受测试覆盖的实现变更同步更新规程和 Skill。
>
> 不使用 CE-04 编号，避免与已规划的 PDF 原文定位 Gold Benchmark 混淆。

## 1. 目的与底线

ChildEvidence 是个人维护的科研证据项目。希望在本地**手动**调用 `$child-evidence-reviewer`，利用当前 Codex 会话所选择的模型审查合法获取、获准进行对应模型处理的科研文献，降低重复人工操作。

遵循 **一次核验、版本绑定、后续复用、变更失效**。不设逐段签署、逐次审批、法务/安全/科研三方固定签字链，也不新建常驻服务或 API 批量执行器。

基本边界：

- **资料使用权限**与**科研审核质量**是两回事。允许提供给模型 ≠ 结果准确 ≠ 人类 Gold。
- **默认拒绝未确认内容**。公开可下载、DOI、库内 license 字段、PDF 内许可文字都可以构成核验证据，但**单一线索不必然等于该具体文件已获准用于当前服务处理**。
- 不处理机构合同禁止外传的全文、非公开资料、儿童个人信息、诊断/用户记录、凭据或已知不受许可覆盖的第三方内容；许可/平台条款冲突时保持拒绝。
- 不上传全文至 Git、公开索引或未批准的第三方服务；模型输出仍为 `silver / L0`，绝不自动改写主库、Gold、知识包或 Agent 行为门禁。

## 2. 只有三档权限

| 状态 | 何时使用 | Codex 使用 |
|---|---|---|
| `allowed` | 已核对具体文件版本及适用许可/使用条件、来源与内容范围；当前 Codex 环境的数据处理设置已确认，且项目负责人完成一次性登记 | 仅本次登记涵盖的文本范围、研究审查目的可使用 |
| `needs_verification` | 只有部分线索，或来源、许可、第三方材料、平台条件、版本等存在实质疑问 | 不向云端模型提供正文/摘要；可本地补证 |
| `restricted` | 已知保密、合同或权利限制，或涉及不可提供的个人/第三方内容 | 阻断；不得靠改名、摘录、OCR、Docling 解析绕过 |

`unknown` 为未分类的初始状态，运行时一律按 `needs_verification` 阻断；无需另增审批层级。

对于作品级 CC0、CC BY 4.0 或经核实的公有领域内容，通常可以作为优先核验来源；不额外要求专门写出“允许 AI”字样，但仍须遵守该版本的具体许可义务、服务/合同条款和内容例外。CC BY-SA 等附条件或许可不明的内容进入 `needs_verification`，按实际条款判断，不机械认定全部违法或全部可用。

## 3. 一篇登记一次，同版本以后复用

建议在 Git 忽略目录下维护本地登记表（例如 `data/review/model-access/permissions.json`），每条仅需：

| 字段 | 要求 |
|---|---|
| `work_id`、`pdf_sha256` | 与原库/PDF 一致；PDF 版本变化则原登记失效 |
| `source_url`、`rights_basis` | 出版商/授权仓储等依据；支持 PDF 内文章级声明的页码与官方页面交叉核对 |
| `scope` | 允许的内容类型：例如 `metadata`、`abstract`、`article_text`；排除不明来源的图表、附录与敏感信息 |
| `decision`、`confirmed_by`、`confirmed_at` | 三档权限与项目负责人一次性确认 |
| `policy_version`、`codex_environment` | 当时的政策版本，以及已检查的 Codex 账户/组织数据设置的记录或指针 |

记录不保存 PDF 正文、摘要或凭据，不入 Git。官方来源/许可证据可本地缓存链接、页面快照哈希；不要求对每一段单独签字。

**一次性检查 Codex 环境及相关数据使用设置；只有设置、账户/组织、政策或权利条件发生影响许可的变化时重新确认。** 每次运行仅自动比对文献 SHA、登记权限及环境信息，写轻量审计记录：`run_id`、work、来源 SHA、实际使用范围、模型实际身份、决策、时间和输出哈希。重跑不再人工重复审批。

## 4. Skill 的最小实现

1. **预检留在本地**：未登记/未获准 → `blocked`；`allowed` 且 SHA/用途/环境与登记一致 → 提供指定范围的审查材料。不能只凭用户输入 `--license CC-BY-4.0` 放行。
2. **获准内容包**：在模型读取之前，本地程序从原始文件构建单次、只读、最小必要的获准文本包（例如文章正文中所需段落），附来源 SHA 和范围；原始 PDF 及完整数据库不直接作为模型输入。若 Codex 工具能越过隔离读取原始文件，提示词不能构成技术保证，需要使用实际文件访问隔离或在受控工作区仅放获准包。
3. **不假设总是需要全文**：`screen` 优先已批准的元数据/摘要；`extract/appraise` 才根据任务使用获准正文；有许可例外的第三方图表等排除。
4. **不动科研层级**：Skill 的 `review.json` 仍 `ai_model / silver / L0`，不能写入人工 `record_signoff`，不能自动发布到 LumiThink。
5. **独立验证**：无权/错版本/受限材料阻断；有权且环境匹配才允许；不通过原始文件改名/Docling/旧审查记录绕过；不改变科研事实源、PDF、Gold、人工历史。

这是一个小规模的 Skill/本地预检改动，不需要新建服务、审核平台、SQLite 迁移、全面文档审批管理系统。

## 5. 现有 35 篇 PDF 的起步方式

既有本地审计统计：`eligible_candidate=2`、`needs_verification=15`、`restricted=4`、`unknown=14`；**原审计时 35/35 出站均为 false**。这不是司法或法律上的“35 篇全部禁止 AI 研究”结论，而是原项目政策与现有证据状态。

优先对 `lt-1ae2bbde5d0f`、`lt-2f7e083d392e` 核对现有 PDF 中 CC BY 4.0 文字对应的正式来源和版本，排除实质性使用限制，并一次性登记。**现在仍是候选，不能只根据本提案自动写 `allowed`。**

条件齐备后，先审查 **1 篇**，验证 Codex 会话实际模型、引文与原文对应、偏倚判断、`unresolved` 处理以及四件归档产物；再扩大至 2、5、10 篇。其余 33 篇不阻挡首篇启动。

## 6. 生效与验收（保持最小闭环）

本 PR 只批准“要不要采用这种简化设计”的讨论，不修改现有 `ANNOTATION_GUIDE.md` 或 `preflight`，也不宣布当前规程生效。

生效前必须由实际项目负责人明确接受适用范围及当前 Codex 环境条件，并另行将相关**已批准条文**和本地登记/预检逻辑同步实现，进行现有全量测试与简要独立复审。若四份科研规程的版本/生效条款需联动，遵守已有治理一致性约束，不由 Agent 代签。

通过后，同一文献的正常日常操作应简化为：**第一次登记 → 以后直接 `$child-evidence-reviewer appraise work_id=...`**；系统自动保留拒绝/放行和科研审查日志。
