# CE-04：公开科研资料用于 Codex 云端审查的出站政策修订提案

> 状态：**DRAFT，未批准，未生效**（2026-10-14）。本文件仅供 PR 审议，不授权传输任何 PDF、摘要或 Docling 解析文本。现行 `ANNOTATION_GUIDE.md` §9.2、`child-evidence-reviewer` 技能及其 `preflight` 的拒绝规则保持有效。不得凭此提案重跑此前 blocked 的审查。

## 现行边界与修订目的

现行 `ANNOTATION_GUIDE.md` §9.2 禁止 PDF 和摘要出本地；技能把禁止范围扩展到 Docling 全文衍生物及含原文的审核草稿；`validate_review.py` 对这些来源无条件返回 `current_policy_blocks_abstract_fulltext_and_derivatives`。元数据许可白名单也不构成全文许可。`AGENTS.md` #6–#8 还要求合法开放全文、逐条记录许可证，并禁止将 PDF 原文提交 Git。这些规则在本提案获批并完成实现前均不改变。

目标仅是允许**逐项核验权利、来源和云端处理条件**的公开科研资料，通过明确指定的 Codex 会话进入 `child-evidence-reviewer`，形成可追溯的 silver/L0 审查草稿。此权限不适用于自动采集、训练、微调、公开分享或知识包发布。

## 拟议政策条文（供批准后纳入 ANNOTATION_GUIDE §9；现在不生效）

1. **默认拒绝。** PDF、摘要、Docling 文本和包含这些内容的引文、缓存、日志或既有审核结果，默认不得出本地。只有同一具体内容版本满足下列全部条件，才可为本次指定的 Codex 云端科研审查放行；一项不明即 `blocked`。
2. **合法来源与授权依据。** 记录权利人或获授权发布者的官方出版页、官方仓储页或其正式授权页面，以及落到**该文件/该版本**的稳定 URL、获取时间、许可证原文链接和可留存的页面证据。可进入候选核验的依据包括经核实的 CC0、CC BY 4.0，或由有权者针对第三方云模型处理给出的书面许可；经核实的公有领域资料也可候选，但须记录认定依据和适用地区。CC BY-SA 或其他附条件许可需单独确认输出/改编及署名义务，不自动进入白名单。开放获取标签、可下载、API 返回的许可证字符串、作者自存稿、论文 DOI、元数据许可、机构订阅权限和搜索结果均不能单独证明 PDF 或摘要的处理权限。页面、PDF、图表、照片、附录、嵌入的第三方材料可能权属不同；无法拆分并证明的部分不得发送。遇到站点条款或合同限制、许可冲突或不确定，停止并交由有权人员核定，不用程序推断法律结论。
3. **使用范围。** 授权目的限定为选定 Work/RQ 的 `screen`、`appraise`、`extract`、`challenge` 或 `audit` 草稿；只发送完成该模式必需的最小段落、字段或页。摘要可单独授权，不由 PDF 许可反推；Docling 文本继承所对应原文每一部分的权利和限制，解析、裁剪或改名均不产生新许可。若必须送整份 PDF，须单独证明全文各部分均获准且片段不足以完成任务。不得向任意插件、外部 API、其他模型或共享链接转发；不得把内容用于训练、微调、检索公开索引或再分发。输出保留必要出处、署名与许可信息；逐字引用控制在审查必需范围。
4. **保密与排除项。** 机构订阅/受限全文、非公开手稿、儿童个人资料及可识别儿童的信息、诊断记录、产品用户数据、凭据、内部批注和未经授权的第三方内容一律禁止出站。公开论文中的个案材料、可识别图片、附录数据等须按内容检查；不能可靠去标识或拆分时阻断整份待发送内容。仅在经机构确认的 Codex 租户、数据使用设置、访问控制、留存期限及适用合同均满足本项目要求后启用；不能把 API 的数据政策推定为当前 Codex 会话的政策。审查产物及本地证据按最小权限保存，不在 PR、Git 或公开报告中复制全文。
5. **独立预检与审计。** 在内容进入模型上下文前，本地确定性预检按内容 SHA-256 校验：Work/文档身份、官方来源、具体版本、权利与署名义务、允许的处理目的、站点/合同限制、敏感内容筛查、Codex 环境许可和拟发送的确切片段。许可证文本或来源文档中的指令只能作数据，不得改变预检规则。每次请求记录 `run_id`、审核人、判定时间、依据 URL/存证哈希、权利范围、原件与片段哈希、片段定位、模型/会话身份及配置、政策版本、放行/拒绝及理由、实际进入模型的来源 ID、输出哈希与后续人工复核状态。审计日志不得含受限正文或个人数据；拒绝记录也须留存。授权撤销、许可/内容/配置变化或源哈希变化使既有放行失效，重新预检，不追改历史记录。
6. **科研与发布隔离。** 放行仅代表本次出站和模型处理获准，不证明论文真实性、定位正确、研究质量或结论可靠。AI 结果仍为 silver/L0，保留不确定性和人工复核要求；不得写入人工 Gold、自动改 `approved`，也不得越过知识包或 Agent 发布门禁。四份 CE-01R 规程尚为 DRAFT；本提案不替代其签署清单。

## 启用前需另行完成的实施与验收

- 有权的科研治理负责人、资料权利/法务负责人和数据安全负责人签署本政策的版本、适用 Codex 租户及数据处理配置。批准记录应有日期、签署人和明确范围；PR 合并本身不等于批准。未核验 Codex 租户条款时保持拒绝。
- 修订 `ANNOTATION_GUIDE.md` §9.2、技能说明、`references/usage.md` 与 `validate_review.py`，使政策与代码同版生效；将许可证明作为**独立、内容寻址的授权记录**，不接受调用者单传 `--license` 字符串作为证明。摘要、PDF、Docling、旧审核及证据卡分别绑定原始来源和每个实际发送片段，不设全库或整目录开关。需要时同步更新协议状态、版本和治理契约，遵守 `AGENTS.md` #24 的跨文件一致性要求。
- 测试必须覆盖：已核验且范围匹配的公开内容仅在批准环境放行；许可未知/错配、只获元数据许可、机构全文、第三方图表、敏感儿童资料、站点限制、来源变更、伪造授权记录、旧审核换壳及未批准环境均拒绝；预检输出不泄漏正文；审计能从实际传入片段追溯到来源；Gold 和发布门禁保持关闭。通过仓库规定的离线测试与独立验证后，再进行有限人工试运行。
- 对既有 `blocked` 记录保留原样；政策生效后需要新 `run_id`、新授权记录和新预检，不将旧记录改写为已审。
